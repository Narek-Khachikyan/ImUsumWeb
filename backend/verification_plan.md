# План проверки работоспособности FastAPI Бэкенда

Этот документ описывает комплексную стратегию тестирования для обеспечения надежности бэкенд-системы перед развертыванием.

## 1. Конфигурация и Окружение (Configuration & Environment)

**Цель**: Убедиться, что приложение корректно инициализируется с правильными настройками.

- **Компоненты**: `pydantic-settings`, `.env`, `logging`.
- **Тест-кейсы**:
   1. **Загрузка переменных**: Проверить, что приложение падает с ошибкой, если отсутствуют критические переменные (`DATABASE_URL`, `SECRET_KEY`).
   2. **Режимы работы**: Проверить поведение `DEBUG=True` vs `DEBUG=False` (уровень логирования, детальность ошибок).
   3. **CORS**: Проверить, что запросы с разрешенных ориджинов (`localhost:5173`) проходят, а с запрещенных блокируются.
   4. **Валидация типов**: Убедиться, что неправильные типы в `.env` (например, строка вместо int для порта) вызывают ошибку валидации Pydantic.
- **Инструменты**: `pytest` (mocking environment variables).

## 2. База данных и Миграции (Database & Migrations)

**Цель**: Гарантировать целостность данных и корректность схемы.

- **Компоненты**: `PostgreSQL`, `SQLAlchemy`, `Alembic`, `asyncpg`.
- **Тест-кейсы**:
   1. **Подключение**: Проверить успешное подключение к БД при старте приложения (Health Check DB).
   2. **Миграции (Up/Down)**: Прогнать `alembic upgrade head`, затем `alembic downgrade base` и снова `upgrade head`. Схема должна быть корректной.
   3. **Транзакции**: Проверить откат транзакции при ошибке (rollback) во время создания связанной сущности (например, User + Student Profile).
   4. **Кодировка**: Проверить сохранение и чтение символов Unicode (армянский/русский текст) в полях `name`, `content`.
- **Инструменты**: `alembic`, `pytest-asyncio` (fixture with transactional rollback).

## 3. Аутентификация и Авторизация (Authentication & Authorization)

**Цель**: Проверить безопасность доступа и управление сессиями.

- **Компоненты**: `api/v1/endpoints/auth.py`, `python-jose`, `passlib`.
- **Тест-кейсы**:
   1. **Регистрация**: Успешное создание пользователя, хеширование пароля в БД (не plain text!).
   2. **Логин (JWT)**: Получение `access_token` и `refresh_token` при верных кредах. Ошибка 401 при неверных.
   3. **Истечение токена**: Попытка доступа к защищенному эндпоинту с истекшим токеном (должен вернуть 401).
   4. **Refresh Flow**: Получение нового access токена с помощью валидного refresh токена.
   5. **Ролевая модель**: Проверить, что обычный `Student` не может удалить ресурс `Assignments`, доступный только `Teacher` (если применимо).
- **Инструменты**: `pytest`, `httpx`.

## 4. API Эндпоинты и Бизнес-логика (API & Models)

**Цель**: Проверить корректность обработки данных и HTTP статусы.

### Пользователи (Users) & Профили

- **Файлы**: `api/v1/endpoints/users.py`, `models/user.py`.
- **Тесты**: Получение профиля (me), обновление данных. Проверка уникальности email.

### Контент (Blogs, Assignments)

- **Файлы**: `api/v1/endpoints/blogs.py`, `assignments.py`.
- **Тесты**:
   - CRUD операции (Create, Read, Update, Delete).
   - Пагинация (проверить `limit` и `offset`).
   - Фильтрация (если есть).
   - Обработка несуществующих ID (404 Not Found).

### Расписание и Оценки (Schedules, Grades)

- **Файлы**: `api/v1/endpoints/schedules.py`, `grades.py`.
- **Тесты**:
   - Проверка формата дат и времени.
   - Привязка оценок к конкретному студенту и заданию.

## 5. Интеграции (AI & External Services)

**Цель**: Проверить взаимодействие с внешними API и отказоустойчивость.

- **Компоненты**: `app/integrations/openai`, `BaseSettings`.
- **Тест-кейсы**:
   1. **OpenAI Live Check**: Отправить тестовый запрос (ping) в OpenAI (только если есть ключ).
   2. **Graceful Degradation**: Отключить интернет/сделать невалидным ключ и проверить, что API возвращает понятную ошибку (503/500), а не падает с трейсбеком.
   3. **Mock Test**: В unit-тестах всегда использовать моки для OpenAI, чтобы не тратить квоту и не зависеть от сети.
- **Инструменты**: `unittest.mock`, `pytest-vcr` (опционально).

## 6. Производительность и Защита (Performance & Security)

**Цель**: Проверить стабильность под нагрузкой.

- **Компоненты**: `slowapi`, `FastAPI`.
- **Тест-кейсы**:
   1. **Rate Limiting**: Отправить X+1 запросов за минуту (где X - лимит) и убедиться в получении 429 Too Many Requests.
   2. **Размер файлов**: Попытка загрузить файл > 10MB (настройка `MAX_FILE_SIZE_MB`). Должна быть ошибка 413.
   3. **Типы файлов**: Загрузка `.exe` или `.sh` файла должна блокироваться (настройка `ALLOWED_FILE_TYPES`).
- **Инструменты**: `httpx`, скрипт нагрузочного тестирования.

# Итоговый Чек-лист (Prioritized Checklist)

### 🔴 Critical (Блокирует релиз)

- [ ] Приложение запускается без ошибок (`uvicorn app.main:app`).
- [ ] Health Check (`/health`) возвращает 200 OK.
- [ ] Подключение к БД работает.
- [ ] Миграции применяются успешно.
- [ ] Регистрация и Логин работают, токены выдаются.
- [ ] Критические переменные окружения валидируются.

### 🟡 Important (Важно для качества)

- [ ] Rate Limiting срабатывает на перегрузку.
- [ ] CRUD операции для основных сущностей (Users, Assignments) работают.
- [ ] Ограничения на загрузку файлов (размер/тип) работают.
- [ ] OpenAI интеграция обрабатывает ошибки (timeout/auth error) корректно.

### 🟢 Desirable (Желательно)

- [ ] Swagger UI (`/docs`) доступен и полни.
- [ ] Логи пишутся в структурированном виде.
- [ ] Проверена работа CORS с реальным фронтендом.

# Рекомендуемый порядок выполнения

1. **Static Analysis & Unit Tests**: Запустить `pytest` для проверки моделей и утилит.
2. **Infrastructure Check**: Проверить Docker (если есть), БД, валидацию конфига.
3. **Migration Check**: Проверить накатывание схемы на чистую БД.
4. **Integration Tests**: Тесты API эндпоинтов на тестовой БД.
5. **Manual/Smoke Test**: Ручная проверка через `/docs` (Login -> Get Token -> Create Assignment).
6. **Load/Limit Check**: Проверка rate limits.
